# 構築手順書

ITSM端末管理システムを、AWS Lightsail上に新規構築する手順です。所要時間の目安は1時間程度です。

- 対象：本システムを公開デモまたは小規模な本番環境として構築する担当者
- 構成：Lightsail（Ubuntu 24.04、1 GBプラン）1台、S3（バックアップ）、Docker Composeで PostgreSQL・API・Caddy を起動
- 構成図：[architecture.png](architecture.png)

> 本書のコマンドは、データベース名とユーザー名が `.env.example` の初期値（`itsm`）であることを前提にしています。
> 変更した場合は読み替えてください。

## 1. 事前準備（作業用PC）

| 必要なもの | 確認方法 |
| --- | --- |
| AWSアカウント（rootではなく、管理用のIAMユーザーまたはSSO） | `aws sts get-caller-identity` |
| Terraform 1.6以上 | `terraform version` |
| AWS CLI v2 | `aws --version` |
| SSH鍵（`~/.ssh/id_ed25519.pub`） | なければ `ssh-keygen -t ed25519` で作成 |
| 通知を受け取るメールアドレス | 予算アラート・証明書の通知に使用 |

**料金の確認：** 作成前に [Lightsailの料金ページ](https://aws.amazon.com/lightsail/pricing/) で最新の料金を確認してください。
本書作成時点（2026年10月）では、パブリックIPv4付きの1 GBプランが月額7米ドル、S3はバックアップ容量が小さいため月0.1米ドル未満の見込みです。
無料利用枠の対象になるかはアカウントによって異なるため、請求コンソールの「無料利用枠」で確認してください。

## 2. AWSリソースの作成（Terraform）

詳細は [infra/terraform/README.md](../infra/terraform/README.md) を参照してください。ここでは流れのみ記載します。

```bash
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars
```

`terraform.tfvars` に次の値を設定します（このファイルはGitに含まれません）。

| 項目 | 設定内容 |
| --- | --- |
| `my_ip` | 作業用PCのグローバルIP＋`/32`（`curl -s https://checkip.amazonaws.com` で確認） |
| `backup_bucket_name` | 世界で一意のバケット名（例：`itsm-backups-tamang-2026`） |
| `alert_email` | 予算アラートの送信先 |

```bash
terraform init
terraform validate
terraform plan -out=tfplan
terraform apply tfplan
```

`plan` の結果が「14 to add, 0 to change, 0 to destroy」であることを確認してから `apply` します。
完了後、次の出力値を控えておきます。

```bash
terraform output
```

| 出力 | 用途 |
| --- | --- |
| `static_ip` | サーバーのIPアドレス |
| `free_domain` | `.env` の `SITE_DOMAIN`（例：`203-0-113-10.sslip.io`） |
| `ssh_command` | SSH接続コマンド |
| `backup_bucket` | `.env` の `BACKUP_S3_BUCKET` |
| `backup_iam_user` | バックアップ用アクセスキーの発行に使用 |

## 3. バックアップ用アクセスキーの発行

アクセスキーはTerraformのstateに残さないよう、CLIで手動発行します。

```bash
aws iam create-access-key --user-name "$(terraform output -raw backup_iam_user)"
```

表示された `AccessKeyId` と `SecretAccessKey` は、手順5でサーバーに登録するまで安全に保管してください。
チャット、メール、Gitには貼り付けないでください。

## 4. サーバーへの接続と初期設定の確認

サーバーは初回起動時に `infra/terraform/cloud-init.sh` を自動実行し、次の設定を行います。

- タイムゾーンを Asia/Tokyo に設定
- 1 GBのスワップを追加（1 GBメモリでのDockerビルド対策）
- セキュリティ更新の自動適用
- Docker Engine と Compose プラグイン、AWS CLI のインストール
- `ubuntu` ユーザーを `docker` グループに追加、ログ用フォルダ `~/itsm-logs` を作成

作成から2～3分待ってから接続し、完了していることを確認します。

```bash
ssh ubuntu@<static_ip>
tail -n 3 /var/log/cloud-init-output.log
```

最終行が `itsm bootstrap finished` であればOKです。続けて各項目を確認します。

```bash
timedatectl | grep "Time zone"
swapon --show
docker compose version
aws --version
```

`docker` コマンドで権限エラーになる場合は、一度ログアウトして再接続してください（グループ設定の反映のため）。

> **Terraformを使わずに構築する場合：** `cloud-init.sh` を root で一度実行すれば同じ状態になります
> （`sudo bash cloud-init.sh`）。

## 5. バックアップ用の認証情報を登録

```bash
mkdir -p ~/.aws
chmod 700 ~/.aws
cat > ~/.aws/credentials <<'EOF'
[default]
aws_access_key_id = <AccessKeyId>
aws_secret_access_key = <SecretAccessKey>
EOF
chmod 600 ~/.aws/credentials
printf '[default]\nregion = ap-northeast-1\n' > ~/.aws/config
```

S3にアクセスできることを確認します（バケット内が空なら何も表示されません）。

```bash
aws s3 ls s3://<backup_bucket>/itsm/
```

## 6. アプリケーションの取得と `.env` の作成

```bash
cd ~
git clone https://github.com/amishanita/itsm-platform.git
cd itsm-platform
cp .env.example .env
chmod 600 .env
```

秘密情報を生成します。

```bash
openssl rand -hex 32     # JWT_SECRET 用
openssl rand -hex 16     # POSTGRES_PASSWORD 用
```

16進数（0～9、a～f）で生成するのは、パスワードがデータベースの接続URLに埋め込まれるためです。
`/` や `@` などの記号を含むとURLとして正しく解釈されません。

`nano .env` で次の項目を設定します。

| 項目 | 設定値 |
| --- | --- |
| `APP_ENV` | `demo`（下記の注意を参照） |
| `POSTGRES_PASSWORD` | 生成した値 |
| `JWT_SECRET` | 生成した値（32文字以上。例の値のままだとAPIは起動しません） |
| `DEMO_PASSWORD` | デモアカウントのパスワード（8文字以上。例の値のままだとデータ投入は拒否されます） |
| `SITE_DOMAIN` | Terraformの `free_domain`、または独自ドメイン |
| `ACME_EMAIL` | Let's Encryptからの通知先 |
| `BACKUP_S3_BUCKET` | Terraformの `backup_bucket` |
| `OPENAI_API_KEY` / `OPENAI_MODEL` | 空欄のままにするとチャットボットは停止します（公開デモでは空欄を推奨） |

`DATABASE_URL` と `FRONTEND_ORIGIN` は `docker-compose.prod.yml` 側で上書きするため、変更不要です。

> **APP_ENVについての注意：** `production` ではデモデータの投入が拒否されます。現在のバージョンには、
> 本番用に最初の管理者アカウントを作成するコマンドがないため、本書は `demo` での構築を前提としています。
> `demo` では4つのデモアカウントが変更不可になり、データは毎晩初期状態に戻ります。

## 7. 起動

```bash
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
```

`db` と `api` が `healthy`、`caddy` が `running` になるまで待ちます（初回はイメージのビルドで数分かかります）。

## 8. マイグレーションとデモデータ投入

```bash
docker compose -f docker-compose.prod.yml exec api alembic upgrade head
docker compose -f docker-compose.prod.yml exec api python -m app.seed
```

2つ目のコマンドの最後に次のように表示されれば成功です。

```
Seed complete: employees=30, users=4, assets=60, kitting_devices=4, loans=8, tickets=80, faq_articles=20
```

## 9. 動作確認

作業用PCから確認します。

```bash
curl -s https://<SITE_DOMAIN>/api/health
```

`{"status":"ok","database":"ok"}` が返ればOKです。ブラウザで `https://<SITE_DOMAIN>` を開き、
`it@demo` と `DEMO_PASSWORD` でサインインできることを確認します。

HTTPS証明書は初回アクセス時にCaddyが自動取得します。証明書エラーが出る場合は [障害対応手順書](障害対応手順書.md) の
「3. 証明書エラー」を参照してください。

## 10. 定期実行（cron）の登録

```bash
crontab -l 2>/dev/null
```

既存の設定がなければ、そのまま登録します（既存の設定がある場合は、上書きされるため内容を統合してください）。

```bash
crontab ~/itsm-platform/scripts/crontab.example
crontab -l
```

登録される処理（時刻は日本時間）：

| 時刻 | 処理 | ログ |
| --- | --- | --- |
| 毎日 03:00 | データベースのバックアップをS3へ保存 | `~/itsm-logs/backup.log` |
| 毎日 03:30 | デモデータを初期状態に戻す（`APP_ENV=demo` のときのみ） | `~/itsm-logs/reseed.log` |
| 毎週日曜 05:00 | 最新のバックアップを別DBに復元して検証 | `~/itsm-logs/restore-check.log` |

`crontab.example` の先頭にある `PATH=` の行は削除しないでください。cronの初期PATHにはAWS CLI
（`/snap/bin`）が含まれないため、この行がないとバックアップが毎回失敗します。

## 11. 初回バックアップとリストア確認

cronを待たずに手動で一度実行し、バックアップから実際に戻せることを確認します。

```bash
cd ~/itsm-platform
scripts/backup.sh
scripts/restore-check.sh
```

それぞれ最後に `backup complete` と `restore check passed` が表示されれば完了です。

## 12. 構築完了チェックリスト

- [ ] `terraform plan` で差分がない（`No changes`）
- [ ] ポート22が自分のIPのみに開いている（`aws lightsail get-instance-port-states --instance-name itsm-app --region ap-northeast-1`）
- [ ] `https://<SITE_DOMAIN>/api/health` が `ok` を返す
- [ ] ブラウザでサインインでき、日本語・英語を切り替えられる
- [ ] `.env` の権限が `600`、`~/.aws/credentials` の権限が `600`
- [ ] cronが登録され、手動のバックアップとリストア確認が成功した
- [ ] 予算アラートのメール送信先が正しい
